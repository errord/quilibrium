# 超图计算映射分析

## 计算如何映射到超图查询

### 核心概念: 计算 ≠ 超图查询

**重要澄清**: 
- 超图用于**状态存储**，不是计算执行
- OT (不经意传输) 用于MPC中的**安全输入传输**
- 计算发生在**乱码电路**中，不是在超图查询中

### 架构层次

```
┌─────────────────────────────────────────────────────────────┐
│                    用户应用层                                 │
│  (提交: 代码 + 输入 + 支付)                                   │

                        │

│              区块链 / 共识层                                  │
```

### 1. 超图在计算中的角色

#### 1.1 超图存储什么

```
超图结构:
====================

顶点 (Vertex): 计算工件
  - 代码部署 (电路二进制)
  - 执行元数据
  - 访问控制信息
  - 结果承诺

超边 (Hyperedge): 关系
  - 代码依赖
  - 数据流连接
  - 权限链接
  - 计算血缘

存储示例:
───────────────
域: 0xabcd... (Compute Intrinsic Domain)

顶点1: 代码工件
  地址: Hash(circuit_binary)
  数据: {
    circuit: <binary_data>,
    input_types: ["int64", "int64"],
    output_types: ["bool"],
    metadata: {
      creator: 0x1234...,
      timestamp: 1234567890,
      version: "1.0"
    }
  }

顶点2: 执行记录
  地址: Hash(execution_id)
  数据: {
    code_ref: Vertex1.Address,
    rendezvous: 0x5678...,
    participants: [Alice_pubkey, Bob_pubkey],
    result_commitment: Hash(result),
    proof: <bulletproof>
  }

超边: 代码→执行
  源: [Vertex1]
  目标: [Vertex2]
  标签: "executed_by"
```

#### 1.2 超图查询操作

```go
// 示例: 检索已部署的代码
func RetrieveCode(domain [32]byte, codeAddress [32]byte) ([]byte, error) {
    // 构造64字节密钥: domain + codeAddress
    key := [64]byte{}
    copy(key[:32], domain[:])
    copy(key[32:], codeAddress[:])
    
    // 查询超图获取顶点数据
    vertexData, err := hypergraph.GetVertexData(key)
    if err != nil {
        return nil, err
    }
    
    // 从VectorCommitmentTree提取电路
    circuit, err := vertexData.Get([]byte{0 << 2}) // 索引0
    return circuit, err
}

// 不是计算查询! 只是数据检索。
```

### 2. 计算执行流程

```
逐步说明: 每个组件在哪里发挥作用
========================================

┌─ 步骤1: 代码部署 ─────────────────────────────────┐
│                                                    │
│  开发者编写QCL代码                                  │
│      ↓                                             │
│  编译为电路 (本地)                                  │
│      ↓                                             │
│  创建CodeDeployment交易                            │
│      ↓                                             │
│  [超图]: 将电路存储到顶点                           │
│      └─► 稍后查询: GetVertexData(code_address)    │
│                                                    │
└────────────────────────────────────────────────────┘

┌─ 步骤2: 执行请求 ───────────────────────────────┐
│                                                  │
│  用户创建CodeExecute交易                          │
│      ↓                                           │
│  [区块链]: 记录请求，支付证明                     │
│      ↓                                           │
│  [超图]: 存储执行元数据                           │
│      └─► 查询: GetVertex(execution_id)          │
│                                                  │
└──────────────────────────────────────────────────┘

┌─ 步骤3: 参与者发现 ───────────────────────────────┐
│                                                    │
│  双方查询超图:                                      │
│      [超图查询]:                                    │
│          GetVertexData(execution_id)              │
│          → 检索rendezvous点                        │
│      ↓                                             │
│  通过P2P连接 (BlossomSub主题)                       │
│      ↓                                             │
│  建立加密通道                                       │
│                                                    │
└────────────────────────────────────────────────────┘

┌─ 步骤4: 电路检索 ───────────────────────────────┐
│                                                  │
│  Garbler查询:                                    │
│      [超图查询]:                                  │
│          GetVertexData(code_address)            │
│          → 检索电路二进制                         │
│      ↓                                           │
│  加载电路到内存                                   │
│  解析门和线                                       │
│                                                  │
└──────────────────────────────────────────────────┘

┌─ 步骤5: MPC执行 (链外!) ──────────────────────────┐
│                                                    │
│  [P2P通道]: 所有计算都在这里发生                    │
│      ↓                                             │
│  Garbler: 生成线标签 (随机)                        │
│  Garbler: 加密真值表                               │
│  Garbler: 发送加密电路给Evaluator                  │
│      ↓                                             │
│  [OT协议]: Evaluator获取输入标签                   │
│      ↓                                             │
│  Evaluator: 逐门计算                               │
│  Evaluator: 发送输出标签回去                       │
│      ↓                                             │
│  Garbler: 解码输出                                 │
│                                                    │
│  注意: 计算期间没有超图查询!                        │
│        超图只用于代码存储/检索                      │
│                                                    │
└────────────────────────────────────────────────────┘

┌─ 步骤6: 结果记录 (可选) ─────────────────────────┐
│                                                  │
│  创建结果承诺                                     │
│      ↓                                           │
│  [超图]: 存储到顶点                               │
│      └─► 稍后查询: GetVertexData(result_id)     │
│                                                  │
└──────────────────────────────────────────────────┘
```

### 3. OT在计算中的作用

```
OT (不经意传输) 目的:
================================

场景: Bob需要他的输入标签，但Alice不应该知道是哪些

不使用OT (不安全):
  Alice: "Bob，你的输入是5 (二进制: 101)"
  Alice: "这里是标签: bit0=L1, bit1=L0, bit2=L1"
  → Alice知道了Bob的输入! ✗

使用OT (安全):
  Alice: 为每个位准备标签对:
    bit0: (L_0, L_1)  ← Bob将选择一个
    bit1: (L_0, L_1)
    bit2: (L_0, L_1)
    
  Bob: "我的输入是5 (二进制: 101)"
        位0 = 1 → OT从标签对0检索L_1
        位1 = 0 → OT从标签对1检索L_0
        位2 = 1 → OT从标签对2检索L_1
        
  Alice: 只知道她发送了3对标签
         不知道Bob选了哪个! ✓

OT协议 (FERRET) 细节:
─────────────────────────────

Alice (发送方):              Bob (接收方):
拥有: (L0, L1) 标签对        拥有: 选择位 (c_i)

1. COT设置
   └─► 生成相关OT基础
   
2. ROT阶段  
   └─► 高效扩展到多个OT
   
3. 对每个位i:
   Alice:                     Bob:
   r0_i, r1_i = Random()      r_i = GetBlock(c_i)
   e0 = r0_i ⊕ L0_i           
   e1 = r1_i ⊕ L1_i           
   Send(e0, e1) ──────────►   
                              L_i = r_i ⊕ e_{c_i}
                              
结果: Bob获得L_{c_i}，Alice不知道c_i
```

### 4. 状态与计算分离

```
┌────────────────────────────────────────────────────────────┐
│                  状态 (超图)                               │
├────────────────────────────────────────────────────────────┤
│  存储内容:                                                  │
│    • 代码工件 (电路)                                        │
│    • 执行元数据                                             │
│    • 访问权限                                               │
│    • 结果承诺                                               │
│                                                            │
│  不做的事情:                                                │
│    ✗ 执行计算                                               │
│    ✗ 处理输入                                               │
│    ✗ Garble/evaluate电路                                   │
│                                                            │
│  查询操作:                                                  │
│    • GetVertexData(address)                                │
│    • AddVertex(domain, address, data)                      │
│    • CreateTraversalProof(keys)                            │
│    • VerifyTraversalProof(proof)                           │
└────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────┐
│              计算 (乱码电路)                                │
├────────────────────────────────────────────────────────────┤
│  发生位置:                                                  │
│    • 链外P2P通道                                            │
│    • 节点间直接通信                                         │
│    • 内存中 (非持久化存储)                                  │
│                                                            │
│  执行的操作:                                                │
│    ✓ Garble电路 (生成标签，加密)                           │
│    ✓ Evaluate门 (解密，计算)                               │
│    ✓ OT协议 (安全输入传输)                                 │
│    ✓ 结果解码                                               │
│                                                            │
│  计算操作:                                                  │
│    • Garble(circuit, inputs)                               │
│    • OT_Send(labels) / OT_Receive(choices)                 │
│    • Evaluate(encrypted_gates, labels)                     │
│    • Decode(output_labels)                                 │
└────────────────────────────────────────────────────────────┘
```

### 5. 为什么采用这种架构？

```
设计理由:
=================

1. 超图用于持久化
   └─► 代码需要跨会话存活
   └─► 结果可能需要稍后验证
   └─► CRDT特性支持分布式共识
   
2. 链外计算
   └─► MPC通信密集 (数MB数据)
   └─► 链上存储昂贵
   └─► 隐私: 计算细节保持私密
   
3. 关注点分离
   ┌─────────────┬──────────────┬──────────────┐
   │    超图     │   区块链     │  P2P+MPC     │
   ├─────────────┼──────────────┼──────────────┤
   │  状态存储   │    共识      │    执行      │
   │ CRDT合并    │    验证      │    隐私      │
   │  持久化     │    排序      │    性能      │
   └─────────────┴──────────────┴──────────────┘
```

## 示例: 计算 "2*32+5-4/33"

```
操作时间线:
=======================

T0: 开发者部署代码
    └─► [超图写入]: 在地址0xABCD存储电路
        └─► AddVertex(COMPUTE_DOMAIN, 0xABCD, circuit_data)

T1: Alice请求与Bob进行计算
    └─► [超图写入]: 存储执行请求
        └─► AddVertex(COMPUTE_DOMAIN, exec_id, {
              code_ref: 0xABCD,
              rendezvous: 0x1234,
              participants: [Alice, Bob]
            })

T2: Alice和Bob相互发现
    └─► [超图读取]: 查询执行元数据
        └─► GetVertexData(exec_id) → rendezvous点

T3: Alice检索电路
    └─► [超图读取]: 加载电路
        └─► GetVertexData(0xABCD) → 电路二进制

T4: MPC执行 (链外，P2P)
    └─► [不涉及超图]
        ├─► Alice garble电路
        ├─► OT传输
        ├─► Bob evaluate
        └─► 计算结果

T5: (可选) 记录结果
    └─► [超图写入]: 存储承诺
        └─► AddVertex(COMPUTE_DOMAIN, result_id, commitment)
```

## 结论

### 超图不是用于计算查询的!

**超图角色**: 
- 📦 代码和元数据的持久化存储
- 🔍 按地址检索数据
- 📜 执行的审计追踪
- 🔐 通过CRDT进行访问控制

**计算角色** (乱码电路 + OT):
- 🔒 隐私保护的执行
- 🚀 链外性能
- 🤝 直接P2P交互
- 🎯 安全输入处理 (通过OT)

**超图是"硬盘"，乱码电路是"CPU"!**
